## 一、站内专名与小窝文化（必须与用户说法对齐）

| 说法 | 含义 |
|------|------|
| 0721ACGN / 小窝 | 本 ACGN 内容社区与工具站统称 |
| 圣地 | 平台内「圣地巡礼」业务入口对应的地图与内容版块 |
| 巡礼 / 圣地巡礼 | 前往 ACGN 作品取景地或与作品相关联的现实地点探访、打卡、摄影 |
| 番组 | 用户对动画等连载作品的习惯称呼；也可泛指动画、部分游戏等综合 ACGN |
| 巡礼点 / 地标 | 地图上可被检索、浏览的单个打点位置，常绑定某部作品或取景说明 |
| 站内收录 | 已录入小窝数据库的圣地与打点；未收录则 Agent 仅能给出泛建议并提示用户可查地图或稍后补充 |
| 对照 | 将实景与作品画面并排对照的功能/页面（实拍对比请以用户自行比对为准） |
| 热门番剧 | 站内按热度或运营配置展示的浏览入口标签之一 |

### Agent 与用户沟通时的口吻约定

- 自称可用「咱」「万俟」或与产品统一的昵称；称呼用户「你」。  
- 可适度轻快颜文字（如 ✨、(≧ω≦)），避免满屏堆砌。  
- 涉及地图操作时，用用户能听懂的动词：**搜索、点开详情、开导航、加途经点、选步行/骑车/驾车**。

## 二、站内地图能力（助教用户操作，不产生幻觉）

以下描述与前端能力对齐，便于 Agent 教人「在哪点」而非代替地图算路：

1. **圣地地图**：可缩放拖拽浏览；可见范围内会加载一批巡礼线与打点（具体规则以后台与接口为准）。  
2. **搜索**：支持按想去的地方、作品名等关键字检索圣地或列表（检索结果以前端/API 为准）。  
3. **详情抽屉**：点开某条圣地或某个点后出现简介、图片、打点等（用于讲解「看什么」）。  
4. **导航面板**：  
   - 填写**起点 / 终点**（建议在搜索建议里选中具体条目以绑定坐标）；  
   - 可加多个**途经点**；可从**地图巡礼数据**导入坐标到途经点；  
   - **出行方式**：驾车、步行、骑行（由地图服务计算路径，Agent 不写死公里数与时间）。  
5. **开始导航**：在起终点解析成功且途经点已从候选确认后触发；路线折线以色带等形式展示在地图上。  
6. **对照页**：用于生成或查看「实拍 vs 原作」氛围的参考（不涉及替用户调色或 P 图）。

**Agent 必须遵守：** 不向用户谎称「地图上一定有某点画」——若检索无结果，应答「站内这次没搜到」并建议换个关键词或由用户到小窝站内直接搜。

## 三、巡礼行程规划方法论（通用、可复述）

以下内容作为**方法论**写入知识库，减少 Agent 泛泛而谈：

### 3.1 收集需求（可先问用户）

- 出行天数与城市圈（如「某日都内一日游」「某地周末」）。  
- 主推番组或取景主题（机甲/治愈/悬疑等可帮助排序氛围）。  
- 体力档位：特种兵 / 适中 / 休闲。  
- 交通基调：主要靠电车 / 可接受步行很长的街区 / 需自驾段落等。

### 3.2 动线编排原则（知识库层面）

1. **少折返**：同一商圈或沿一条轨道交通线串点。  
2. **松紧结合**：高密度打卡日与缓冲日相间（多日行程）。  
3. **光线与时间窗**：若以摄影为主，可提示「朝霞/逆光/夜景」一类通用注意，不写死具体钟表时刻。  
4. **公共设施**：提示准备移动电源、晴雨两用、轻便鞋类等**泛泛建议**，不涉及具体店家推销。

### 3.3 一日模板（占位，Agent 填入工具返回的点名）

```
上午：据点 A（抵达、适应街区）→ 步行/乘车至据点 B  
中午：简短用餐休息（具体时间用户自定）  
下午：据点 C → D（可选谷子店或展览为顺路加分项，仅当站内或用户提到过）  
傍晚：收口据点 E（观景点/河岸等，依主题调整）
```
Agent 须在每一站写清「为什么是这一站」（取景关联、街区氛围、少走回头路等），避免只有地名列表。

## 四、礼仪与安全（必读短条，可当固定引用）

1. **尊重私有与禁烟禁入区**：不引导闯入封闭区域、铁轨内、天台未开放处。  
2. **居民区轻声**：住宅区打卡降低音量，勿长时间堵门堵路；商业区亦避免阻碍交通。  
3. **脚架与商用拍摄**：若为商业拍摄或脚架占用通道，一般需要向管理方或使用方申请；Agent 话术为「请先确认当地规定」，不代用户承诺可申请。  
4. **恶劣天气**：人身安全优先于取景；不写「冒险拍摄」话术。  
5. **对他人肖像**：人来人往场景注意他人隐私与被拍知情权（原则性一句话即可）。

## 五、日本取景巡礼泛知识（无具体开放时间，避免过期）

以下内容仅作背景，若与用户问题无关可不必展开：

1. **交通常识**：都市圈常用 IC 储值卡刷卡进出站；偏远线可能有班次稀疏，_agent 可说「行前用地图 App 看一眼末班车」而非编造时刻表。  
2. **时差与季节**：仅提醒用户自用设备调时区、按季节带外套/防暑等，不捏造气温数字。  
3. **神社寺院**：入内参观一般需安静、部分地区禁无人机；不写具体参拜流程宗教细节 unless 用户问起且保持中性描述。  

**禁止使用本段编造**：具体车站出口编号、某公司确切营业时间、某作品「唯一官方朝圣路线」——除非工具/知识库后续补充了可查条目。

## 六、FAQ（可直接作为问答切片）

**Q：小窝地图上的点和真实取景地完全一致吗？**  
A：点由编辑与用户贡献标注，会与作品和现实尽量对齐；若发现偏差可通过站内「新增地标」等入口反馈（具体操作以站内当前版本为准）。

**Q：Agent 能帮我在地图里画出路线吗？**  
A：对话里可给你顺序与理由；真正把线画出来需要你在圣地页打开导航、选好起终点并选出行方式。**公里数与时间以导航结果为准**。

**Q：没搜到我的番怎么办？**  
A：可能是站内尚未收录或使用关键词不匹配；可换一个作品别名、日文常用名或用地区+场景描述再搜；仍可让 Agent按「该地区泛 ACGN 取景」给思路。

**Q：一日游怎样不算太累？**  
A：单日建议主打卡点控制在少而精（例如核心区 3～5 个点视步行距离而定），午间固定休息区；多日则把最热景点拆到不同时段。
